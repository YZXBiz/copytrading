# Acceptance journeys

"Working" means every journey below passes against the real app window, not only its unit tests.
Each journey is automated in `app/scripts/ui_journeys.py` and runs against a debug build with an
isolated state root, so it never reads or writes your real configuration, Keychain items, or ledger.

Journeys marked **needs …** run only when the matching credentials are supplied through the
environment (`COPYTRADING_TEST_ALPACA_KEY`, `COPYTRADING_TEST_ALPACA_SECRET`, and for J27 and J31 also
`COPYTRADING_TEST_DEEPSEEK_KEY`, `COPYTRADING_TEST_DISCORD_TOKEN`, `COPYTRADING_TEST_DISCORD_CHANNEL`); without them the journey is
reported as skipped, never as passed. The runner never echoes typed values in its errors.

## Design bar

Every journey also captures a screenshot of each screen it visits, in light and dark mode. A
journey fails on visible defects: clipped or overlapping text, raw `snake_case` codes, raw ISO
timestamps, empty panes with no explanation, or controls enabled when their action cannot succeed.
